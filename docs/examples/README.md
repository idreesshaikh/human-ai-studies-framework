# Worked example: pilot-2026

A complete, reproducible end-to-end run of the pipeline on the bundled
protocol  -  from the protocol to a Jupyter notebook, with a synthetic dry run
in between. Every file here was **generated by the tools in this
repo**, not hand-written.

## What is in here

| File | What it is | How it was produced |
| --- | --- | --- |
| `protocol.yaml` | The study protocol (copy of `protocol/examples/pilot-study.yaml`) | boot-loaded by the middleware via `MIDDLEWARE_PROTOCOL` |
| `dry-run-report.md` | Analysis report over synthetic data: one section per recipe, each traced to a research question | `python -m middleware simulate pilot-2026 --count 10 --seed 42 --protocol protocol.yaml` |
| `data-dictionary.md` | Every event type, field, and metric column the analysis layer can consume | `python -m analysis.cli notebook --dictionary-only` (see the notebook command) |
| `notebook.ipynb` | Starter Jupyter notebook: imports the curated dataset, runs the planned recipes, keeps the researcher's own analysis cells empty | `python -m analysis.cli notebook` |
| `<recipe>/` | Figures (png/svg), CSV tables, and per-recipe markdown summaries  -  **not committed**: generated output, regenerable with the one command in step 2 | `analysis run`, invoked by the simulate CLI |

The tracked files are the curated, human-readable artifacts (protocol, report,
notebook, data dictionary); everything else the pipeline
produces  -  the per-recipe figures and tables  -  is generated output that stays
out of the repository. A CI regression test
(`middleware/tests/test_worked_example.py`) re-runs the pipeline hermetically
and fails if the tracked artifacts drift from what it produces.

## Reproduce it

```bash
# 1. boot the middleware with the bundled protocol (any port, any DB)
MIDDLEWARE_PROTOCOL=protocol/examples/pilot-study.yaml \
MIDDLEWARE_DB=/tmp/pilot-2026.sqlite3 MIDDLEWARE_PORT=8000 \
uv run python -m middleware serve

# 2. dry-run 10 synthetic participants (seeded -> reproducible)
uv run python -m middleware simulate pilot-2026 \
  --server http://127.0.0.1:8000 --count 10 --seed 42 \
  --protocol protocol/examples/pilot-study.yaml

# 3. generate the starter notebook + data dictionary
uv run python -m analysis.cli notebook protocol/examples/pilot-study.yaml \
  --server http://127.0.0.1:8000 --out .

```

The dry run is reproducible by construction: the same `--seed` against a
fresh database produces the same dataset (session ids carry a per-run nonce
and are stripped before comparison).

## Why this matters for the pilot

- **The pipeline works before any participant does.** The notebook, data
  dictionary, and report are generated from the same plan the real data
  will be validated against.
- **Instrumentation gaps surface immediately.** A recipe that cannot run on
  synthetic data is almost certainly a gap that would also bite real
  captures; every recipe ran clean here (10/10).
- **The report is the traceability artifact.** Each section names the
  research question it answers, satisfying the FR-DASH-6 / FR-ANA-4
  requirement that analyses be traceable to the protocol.
