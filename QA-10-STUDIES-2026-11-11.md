## Campaign-wide result

The 10 distinct study agents were launched in waves: the runtime caps the
coordinator plus three QA agents at a time. All 10 study tracks and the final
post-session export checks are complete.

The current code gates are green: the combined Python suite passed 1,359 tests
with 1 expected xfail and 6 upstream deprecation warnings; extension 252 tests,
TypeScript/lint/format checks and scripted replay passed; platform build, lint,
contrast and the full browser regression harness passed. The updated
flagged-session label and exclusion workflow passed the browser regression. Its
post-change accessibility audit passed 30 WCAG 2.2 AA rules with zero violations
across desktop, tablet, mobile, and narrow viewports in light and dark themes. The
extension replay covers 28 edit-origin scenarios (7 known capture-boundary
mismatches documented below) and 10 stuck-detection scenarios with zero false
alarms. The final Python run covered analysis, protocol, middleware, and
agent-capture.

## Defects found and resolved

- Chat protocol review hid Apply for a valid server compile because the client
  preview omitted template-provided instruments and recipes. The draft now uses
  the authoritative compile only for the move ledger it compiled.
- Cross-file paste/AI-accept correlation could relabel the wrong edit burst;
  correlation now includes the destination file. Scroll-reading also no longer
  triggers stuck prompts; the scripted replay has zero false alarms.
- Transcript normalization crashed on malformed rows, numeric/bearer/escaped
  secrets escaped redaction, and workspace snapshots included their own shadow
  Git tree. All three have focused regression tests.
- Viewer role support was inconsistent across the capability model, owner route,
  and database constraint. Credentialed event/metric ingestion also permitted
  cross-study or cross-participant writes. Viewer migration and atomic ownership
  checks now cover these cases.
- “Trust in AI” matched the generic BFI-2 interpersonal trust facet. The catalog
  alias now requires the more specific “interpersonal trust” phrase.
- Pre-task baseline covariates appeared as outcome-review warnings. The outcome
  checker now reports them as covariates, not repeated condition outcomes.
- TERN reused a participant's enrollment condition after a within-subject block
  advanced, so valid events were flagged against the server's assigned block.
  Session start now uses the refreshed block condition for the recorder and
  condition-specific surveys.
- The AI reliance debrief used a case-sensitive arm check, which omitted its item
  for a server-issued `AI-assisted` label. Condition matching now ignores case;
  the paired run saved the AI-reliance answer. A pause/status-menu race that
  could lose a scheduled fatigue answer is now recorded as an interruption and
  retried; native VS Code reproduced the fix, pending status survives crash
  snapshots, and explicit Esc remains a participant skip.
- Crash recovery continued event sequence correctly but reduced the monotonic
  timestamp after the extension host restarted. Recovery now rebases on the last
  persisted `mono` value (or active elapsed time if that is greater); helper and
  sink regressions pass, and a live restart verified monotonic continuity.
- The Data page equated a complete event sequence with unflagged capture. It now
  reports flagged-event counts independently from sequence completeness. A
  browser regression covers a complete but flagged session, exclusion, and
  persisted row annotations; the live failed P02 run now shows 50 flagged events
  and can be excluded from the chart.
- The direct dataset CSV omitted pilot and session-exclusion metadata even though
  JSON and ZIP exports retained it. The CSV now includes `pilot` and
  `inclusionDecision`; 16 focused route/export tests verify a flagged excluded
  row carries both, and final CSV/ZIP artifacts retain both P02 exclusions.
- Extension type-check caught a stale suggestion-id property after a lifecycle
  hook was removed; that compile error is fixed. QA assertions were also updated
  for the expanded measure catalog and capture-count analysis semantics.

## Limits recorded during testing

- The live model-provider probe returned HTTP 429 on its first synthetic prompt;
  chatbot workflow coverage therefore uses the deterministic scripted assistant.
- Native VS Code consent UI is outside renderer CDP automation, so the linked
  consent click was not covered in the first linked pair run; the separate
  30-minute run accepted consent in native VS Code.
- Scripted edit-origin calibration has seven documented edge mismatches: context
  menu/drag-drop pastes and events outside narrow AI/paste correlation windows.
  The extension validation report labels these blind spots; this is not a
  precision/recall estimate for real developer sessions.
- The 30-minute IDE run was synthetic QA evidence, not human-participant data.
  It contains two pre-fix incidents and is excluded from analysis in the study
  plan; the corrected prompt/recovery and timestamp paths were verified live.
  It covered only P02 in the AI-assisted condition and produced no task-outcome
  metric rows, so it does not support a condition comparison. Chart inclusion,
  exclusion, and rendering were exercised with synthetic platform fixtures.
